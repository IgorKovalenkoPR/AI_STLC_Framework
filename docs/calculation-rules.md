# Правила розрахунку `Actual, %`

Реалізація — `apps-script/Compute.gs`; 20 тест-кейсів — `apps-script/Test.gs`
(`node tools/run-tests.js`).

## Формат: частка, не відсоток

У таблиці Target зберігається як **`-0.3` з відсотковим форматом**, а не як `-30`.
Actual пишеться так само — часткою. Запис `-30` у комірку з форматом `0.0%` дав би
«−3000,0%». Це найтиповіша помилка такої інтеграції, тому вона покрита тестами.

## Знак

| Фази | Що є покращенням | Знак Actual |
|---|---|---|
| 1, 2, 3, 4, 6, 7, 8 | скорочення часу / зусиль | **від'ємний** (більший мінус кращий) |
| 5 — Виконання тестів | приріст пропускної здатності | **додатний** (більше краще) |

Тім-лід ніколи не вводить знак вручну — ні в годинах, ні в оцінці діапазоном.
Скрипт підставляє його з `phase.sign`.

## Пріоритет джерел

**1) виміряні години → 2) оцінка діапазоном → 3) текстова мітка зі статусу.**

```
Крок 0. Статус ∈ {NA_PRODUCT, NA_NDA, NA_TOOLING}
        → відповідна текстова мітка. КІНЕЦЬ.
        Якщо при цьому були введені години — вони ігноруються,
        у Журнал відповідей пишеться попередження про суперечність.

Крок 1. Статус = NOT_YET → "0% — ще не використовуємо". КІНЕЦЬ.

Крок 2. Статус відсутній → нічого не пишемо, попередження в лог. КІНЕЦЬ.

Крок 3. Є валідна пара (baseline B, with-AI A):
          B = 0  → пропускаємо (ділення на нуль), попередження, йдемо на крок 4
          фаза 5 → v = +(A − B) / B
          інакше → v = −(B − A) / B

Крок 4. Інакше, якщо обрано діапазон (крім "Не застосовно"):
          m = midpoint діапазону
          фаза 5 → v = +m ; інакше v = −m

Крок 5. Інакше → "Немає даних".

Крок 6. v округлюється до 3 знаків (0,1 п.п.).
        |v| > 0.9 → значення пишеться, але позначається як outlier.
        Знак, протилежний очікуваному → попередження «регресія vs baseline».
```

Порядок кроків 0–1 навмисний: «неможливо» перекриває будь-які цифри. Якщо фаза позначена
як недоступна через NDA, число в таблиці ввело б в оману незалежно від того, що хтось
ввів у полі годин.

## Перевірка на прикладах

| Фаза | Ввід | Розрахунок | Actual | Target | Колір |
|---|---|---|---|---|---|
| 3. Дизайн тестів | `5 / 3.5` | −(5−3.5)/5 | **−30,0%** | −28% | 🟢 зелений |
| 1. Requirements | `8 / 5` | −(8−5)/8 | **−37,5%** | −30% | 🟢 зелений |
| 2. Планування тестування | `16 / 14` | −(16−14)/16 | **−12,5%** | −25% | 🔴 червоний |
| 5. Виконання тестів | `6 / 7.5` | +(7,5−6)/6 | **+25,0%** | +18% | 🟢 зелений |
| 5. Виконання тестів | `8 / 8` | +(8−8)/8 | **0,0%** | +18% | 🔴 червоний |
| 1. Requirements | `8 / 10` (стало гірше) | −(8−10)/8 | **+25,0%** | −30% | 🔴 червоний + попередження |
| 6. Defect Mgmt | `20,0 ; 13` | −(20−13)/20 | **−35,0%** | −33% | 🟢 зелений |
| 7. Завершення тестування | діапазон `30–40%` | −0,35 | **−35,0%** | −30% | 🟢 зелений |
| 8. Автоматизація тестування | діапазон `Без змін (0%)` | 0 | **0,0%** | −30% | 🔴 червоний |

Приклад із «Legend & Sources» вихідної таблиці (Дизайн тестів: 16 год вручну → 11 год з AI)
дає `−(16−11)/16 = −31,25%` → округлення до **−31,3%**, зелений при таргеті −28%. Збігається
з очікуванням у легенді (−31%).

## Розбір вводу

- Роздільник пари: `/` або `;`.
- Десятковий роздільник: крапка або кома (`12,5` = `12.5`) — під українську розкладку.
- Пробіли ігноруються.
- Не розпізнаний рядок (`about five hours`) не ламає обробку — спрацьовує фолбек
  на оцінку діапазоном, а якщо її немає — `Немає даних`.

Валідація у формі не пропускає більшість помилок ще на боці респондента, але скрипт
не покладається на неї: відредаговані відповіді та імпортовані дані валідацію обходять.

## Перевірка досягнення Target

```js
meetsTarget(phase, value) = phase.sign > 0 ? value >= phase.target
                                           : value <= phase.target
```

Порівняння працює лише для числових Actual. Текстові мітки не порівнюються з Target —
вони мають власні кольори (див. `mapping-spec.md`).

## Оцінки vs заміри

Обидва джерела пишуть число в ту саму комірку — свідоме рішення: менеджменту потрібна
повна картина по всіх 16 проєктах, а не 5 «чесних» цифр і 11 порожніх клітинок.
Різниця фіксується у трьох місцях:

1. примітка до комірки — рядок `Actual: … (measured)` або `(estimated)`;
2. примітка — `Confidence` з Q23;
3. `Журнал відповідей` — колонка `Written values` і сам статус фази.

Якщо політика зміниться і оцінки треба буде відділити візуально — це одна зміна
в `WriteSheet.gs` (писати `~-25% (est.)` текстом) плюс правило форматування.
