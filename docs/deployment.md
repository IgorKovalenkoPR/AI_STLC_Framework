# Розгортання

Час: ~15 хвилин. Виконує власник таблиці (QA-менеджер).

## Передумови

- Google-акаунт з правом створювати Google Forms і Apps Script.
- Файл `templates/AI_QA_Optimization_Target_vs_Actual.xlsx`.

> **Важливо про формат.** Apps Script не вміє писати у `.xlsx` напряму. Джерелом правди
> стає **Google Таблиця**; `.xlsx` для клієнта/звіту вивантажується наприкінці періоду
> через `Файл → Завантажити → Microsoft Excel (.xlsx)`.

## Крок 1. Конвертувати таблицю в Google Sheets

1. Завантажити `AI_QA_Optimization_Target_vs_Actual.xlsx` на Google Drive.
2. Відкрити → `Файл → Зберегти як Google Таблиці`.
3. Перевірити після конвертації:
   - вкладка називається **`AI QA Optimization`** (якщо ні — запам'ятати назву для кроку 3);
   - рядки 1–3 лишились об'єднаним заголовком, дані починаються з рядка 4;
   - колонки Target (E, G, I, K, M, O, Q, S) показують `-30%`, `-25%`, … (тобто зберігся
     відсотковий формат, а всередині лежить `-0.3`, а не `-30`).

## Крок 2. Створити проєкт Apps Script

1. У таблиці: `Розширення → Apps Script`.
2. Видалити файл-заглушку `Code.gs`.
3. Створити файли з каталогу `apps-script/` — **назва в назву**, без розширення
   (`Config`, `BuildForm`, `Parse`, `Compute`, `WriteSheet`, `Maturity`, `Formatting`,
   `Triggers`, `Recompute`, `Menu`, `Test`) і вставити вміст відповідних `.gs`.
4. `Налаштування проєкту` → увімкнути **«Показувати файл маніфесту appsscript.json»**,
   відкрити `appsscript.json` і замінити його вмістом з `apps-script/appsscript.json`.

> Якщо під час авторизації Google скаржиться на скоупи — можна видалити весь блок
> `oauthScopes` з маніфесту: Apps Script визначить потрібні дозволи автоматично.

## Крок 3. Задати властивості скрипта

`Налаштування проєкту → Властивості скрипта → Додати властивість`:

| Ключ | Значення | Обов'язково |
|---|---|---|
| `ACTIVE_PERIOD` | період, який відображає таблиця, напр. `Q3 2026` | так |
| `OWNER_EMAIL` | пошта для сповіщень про нові проєкти й попередження | ні, але варто |
| `SHEET_NAME` | назва вкладки, якщо вона **не** `AI QA Optimization` | ні |

Список періодів у випадному списку форми задається константою `PERIODS` у `Config.gs`.

## Крок 4. Запустити `setup()`

1. У редакторі обрати функцію **`setup`** → `Запустити`.
2. Пройти OAuth-консент (екран «Google не перевірив цей додаток» → `Додатково → Перейти…`
   — це нормально для власного скрипта).
3. У логах (`Ctrl/Cmd + Enter`) з'явиться посилання на форму. Воно ж зберігається у
   властивостях скрипта і доступне через меню **AI STLC ▸ Show form link**.

`setup()` за один прохід: створює форму, прив'язує її до цієї ж таблиці, створює аркуші
`Submission log`, `AI Maturity`, `Coverage`, накладає умовне форматування і вішає тригер
`onFormSubmit`. Повторний запуск безпечний — наявна форма перевикористовується.

## Крок 5. Перевірити на тестовій відповіді

1. Відкрити форму, обрати проєкт **Auris**, період = `ACTIVE_PERIOD`.
2. У сітці «Do you use AI in this phase» поставити:
   - `3. Test Design` → `Yes — used & measured`
   - `4. Environment Setup` → `No — product / project specifics`
   - `8. Test Automation` → `No — no automation / CI-CD / tooling`
   - решту — на власний розсуд.
3. На кроці «How can you report the impact?» обрати `I have measured numbers`.
4. У полі Phase 3 ввести `5 / 3.5`. Надіслати.

Очікуваний результат у рядку `Auris` (рядок 5):

| Комірка | Значення | Колір |
|---|---|---|
| `J5` (Test Design, Actual) | `-30.0%` | зелений (Target `-28%` перевищено) |
| `L5` (Environment Setup) | `N/A — product specifics` | сірий |
| `T5` (Test Automation) | `N/A — no automation / CI-CD` | сірий |

У `J5` має бути примітка з розрахунком, джерелом (`5 / 3.5`), статусом, рівнем довіри,
періодом і автором. У `Submission log` — рядок з `action = UPDATE`.

Після перевірки видалити тестову відповідь: у формі `Відповіді → ⋮ → Видалити всі відповіді`,
потім у таблиці меню **AI STLC ▸ Recompute all from responses**.

## Крок 6. Роздати посилання

Надіслати тім-лідам посилання на форму разом із [faq-teamleads.md](faq-teamleads.md).

За бажанням увімкнути щотижневе нагадування тим, хто не відзвітував: у редакторі
запустити функцію `installWeeklyReminder` (лист приходить щопонеділка о 9:00 на `OWNER_EMAIL`).

## Тести

Розрахунковий шар не залежить від Google API і перевіряється локально:

```bash
node tools/run-tests.js
```

У таблиці — меню **AI STLC ▸ Run self-test** (нічого не змінює, лише рахує).

## Траблшутинг

| Симптом | Причина / що робити |
|---|---|
| `ITEM_MAP is missing` | Форму створювали не через `setup()`/`Rebuild form`. Запустити **Rebuild form** |
| `Sheet "AI QA Optimization" not found` | Вкладку перейменували → задати `SHEET_NAME` у властивостях скрипта |
| Відповідь надійшла, комірки порожні | Період відповіді ≠ `ACTIVE_PERIOD` → у `Submission log` буде `ARCHIVED_ONLY` |
| `PROJECT_NOT_FOUND` у лозі | Проєкт обрали зі списку, але рядка в колонці B немає. Додати рядок або доповнити `PROJECT_ALIASES` |
| Тім-лід відредагував надіслану відповідь, а таблиця не змінилась | Редагування не завжди запускає тригер → меню **Recompute all from responses** |
| Комірки не фарбуються | Меню **Reapply conditional formatting** |
