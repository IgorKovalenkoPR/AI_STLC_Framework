## Крок 1. Створити проєкт Apps Script

1. Відкрити таблицю → `Розширення → Apps Script`.
2. Видалити файл-заглушку `Code.gs`.
3. Створити файли з каталогу `apps-script/` — назва в назву, без розширення
   (`Config`, `BuildForm`, `Parse`, `Compute`, `WriteSheet`, `Maturity`, `Formatting`,
   `Triggers`, `Recompute`, `Menu`, `Test`) і вставити вміст відповідних `.gs`.
4. `Налаштування проєкту` → увімкнути **«Показувати файл маніфесту appsscript.json»**,
   відкрити `appsscript.json` і замінити його вмістом з `apps-script/appsscript.json`.

> Якщо Google скаржиться на скоупи під час авторизації — видаліть увесь блок
> `oauthScopes` з маніфесту: Apps Script визначить потрібні дозволи сам.

## Крок 2. Задати властивості скрипта

`Налаштування проєкту → Властивості скрипта → Додати властивість`:

| Ключ | Значення | Обов'язково |
|---|---|---|
| `ACTIVE_PERIOD` | період, який відображає таблиця, напр. `Q3 2026` | так |
| `OWNER_EMAIL` | пошта для сповіщень про нові проєкти й попередження | ні, але варто |
| `FORM_ID` | інший ID форми, якщо працюєте не з тією, що в `Config.gs` | ні |
| `SHEET_NAME` | назва вкладки, якщо вона не `AI QA Optimization` | ні |
| `TARGET_SPREADSHEET_ID` | ID таблиці, якщо вона **не** та, до якої прив'язаний скрипт | ні |

Список періодів у формі задається константою `PERIODS` у `Config.gs`.

## Крок 3. Запустити `setup()`

1. У редакторі обрати функцію **`setup`** → `Запустити`.
2. Пройти OAuth-консент (екран «Google не перевірив цей додаток» → `Додатково → Перейти…`
   — це нормально для власного скрипта).
3. У логах (`Ctrl/Cmd + Enter`) з'явиться посилання на форму.

Що робить `setup()` за один прохід:

- **наповнює вашу форму** — видаляє поточні елементи (зокрема порожній placeholder)
  і будує 24 елементи заново; **посилання на форму не змінюється**, зібрані раніше
  відповіді не зникають;
- перевіряє прив'язку до таблиці (вона вже є — повторно не перепідключає);
- створює аркуші `Журнал відповідей`, `Зрілість AI`, `Покриття`;
- накладає умовне форматування на колонки `Actual, %`;
- ставить тригер `onFormSubmit`.

Повторний запуск безпечний.

## Крок 4. Прибрати старий стовпець у відповідях

Аркуш `Form Responses 1` зараз має колонку `Untitled Question` від порожнього
placeholder-питання. Після наповнення форми вона стає зайвою: видаліть цей стовпець
вручну (правий клік на заголовку → `Видалити стовпець`). Нові колонки під питання
Google додасть сам при першій відповіді.

## Крок 5. Перевірити на тестовій відповіді

1. Відкрити форму, обрати проєкт **Auris**, період = `ACTIVE_PERIOD`.
2. У сітці «Чи використовуєте ви AI на цій фазі» поставити:
   - `3. Дизайн тестів` → `Так — використовуємо і маємо заміри`
   - `4. Налаштування середовища` → `Ні — специфіка продукту / проєкту`
   - `8. Автоматизація тестування` → `Ні — немає автоматизації / CI-CD / інструментів`
   - решту — на власний розсуд.
3. На кроці «На основі чого ви можете оцінити ефект?» обрати `Маю виміряні цифри (було / стало)`.
4. У полі фази 3 ввести `5 / 3.5`. Надіслати.

Очікуваний результат у рядку `Auris` (рядок 5):

| Комірка | Значення | Колір |
|---|---|---|
| `J5` (Дизайн тестів) | `-30,0%` | зелений (Target −28% перевищено) |
| `L5` (Налаштування середовища) | `N/A — специфіка продукту` | сірий |
| `T5` (Автоматизація тестування) | `N/A — немає автоматизації / CI-CD` | сірий |

У `J5` має бути примітка з розрахунком, джерелом (`5 / 3.5`), статусом, рівнем довіри,
періодом і автором. У `Журналі відповідей` — рядок з дією `ЗАПИС`.

Після перевірки: у формі `Відповіді → ⋮ → Видалити всі відповіді`, потім у таблиці
меню **AI STLC ▸ Перерахувати все з відповідей**.

## Крок 6. Роздати посилання

Надіслати тім-лідам посилання на форму разом із [faq-teamleads.md](faq-teamleads.md).

За бажанням увімкнути щотижневе нагадування тим, хто не відзвітував: запустити в
редакторі функцію `installWeeklyReminder` (лист щопонеділка о 9:00 на `OWNER_EMAIL`).

## Тести

Розрахунковий шар не залежить від Google API:

```bash
node tools/run-tests.js
```

У таблиці — меню **AI STLC ▸ Запустити самоперевірку** (нічого не змінює).

## Траблшутинг

| Симптом | Причина / що робити |
|---|---|
| `Немає ITEM_MAP` | Форму наповнювали не через скрипт. Меню **AI STLC ▸ Наповнити форму зі скрипта** |
| `Аркуш «AI QA Optimization» не знайдено` | Вкладку перейменували → задати `SHEET_NAME` у властивостях скрипта |
| Відповідь надійшла, комірки порожні | Період відповіді ≠ `ACTIVE_PERIOD` → у журналі буде дія `ІНШИЙ ПЕРІОД` |
| `ПРОЄКТ НЕ ЗНАЙДЕНО` у журналі | Проєкт обрали зі списку, але рядка в колонці B немає. Додати рядок або доповнити `PROJECT_ALIASES` |
| Тім-лід відредагував надіслану відповідь, а таблиця не змінилась | Редагування не завжди запускає тригер → меню **Перерахувати все з відповідей** |
| Комірки не фарбуються | Меню **Оновити умовне форматування** |
| У формі з'явилось зайве питання | Його додали кліками в UI. Скрипт його ігнорує — перенесіть зміну в `BuildForm.gs` і наповніть форму заново |
